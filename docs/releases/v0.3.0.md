# ShieldSpec v0.3.0 — GitHub Action/source release

The v0.3.0 source tag introduces opt-in differential CI for wallet developers. This release has no prebuilt binaries. The independently versioned crates.io packages remain at v0.2.0; no v0.3.0 crate publication is claimed.

## New GitHub Action mode

- `mode: snapshot` remains the default, preserving the v0.2.0 Action's baseline/candidate snapshot checks and exit statuses.
- `mode: differential` with `preset: zcash-sdk` builds ShieldSpec's pinned first-party SDK runner and compares it with itself. This is an onboarding negative control, **not** testing the caller's wallet or a different SDK revision.
- `mode: differential` with `preset: custom` accepts two executable runner paths built by the caller for a genuine compatible wallet/SDK implementation comparison.
- Configurable deterministic `seed`, `cases`, `scenario-family`, policy and newline-delimited runner arguments.
- JSON campaign reports and minimized discovery evidence, when present, are uploaded as GitHub Actions artifacts before the final 0/1/2 status is enforced.

## Compatibility and limits

- Snapshot mode is backwards compatible; `candidate` is now validated at execution time because it is not needed in differential mode.
- Rust 1.95.0 and the same pinned Zcash SDK prerelease dependencies remain in use.
- The Action builds its own fuzzing tooling, but does not automatically clone or build arbitrary third-party wallets, manage their credentials, sign/broadcast transactions, prove anonymity or classify every changed wallet-policy verdict as a vulnerability.
- The four crates.io packages (`shieldspec-core`, `shieldspec-testkit`, `shieldspec-cli`, `shieldspec-zcash`) stay at 0.2.0. The nonpublishable fuzzer/runner crates are still built from the source tag.

See [developer CI integration](../ci-integration.md) and [runner protocol](../runner-protocol-contract.md). The v0.2.0 GitHub Action tag is unchanged and remains snapshot-only.
